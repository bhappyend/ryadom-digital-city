## 0. Обязательная организация работы: «Одна задача — один чат»

Работай внутри одного общего проекта «Рядом» by Patchvale. Не выполняй весь проект в одном длинном диалоге. Обязательное правило: одна самостоятельная задача (или отдельное согласованное направление разработки) — один отдельный чат в этом же проекте. Ты сам создаёшь и именуешь рабочие чаты, распределяешь задачи, передаёшь контекст и контролируешь результат. Не перекладывай организацию чатов на заказчика, если среда позволяет создавать их программно.

Главный чат — «00 | Рядом — Координатор проекта». Он отвечает за декомпозицию, зависимости, архитектурные решения, общий план, координацию и приёмку. До начала реализации самостоятельно сформируй следующие рабочие чаты по мере необходимости, строго внутри общего проекта и с общим репозиторием:

| Чат | Зона ответственности |
|---|---|

| 02 \| UI/UX и дизайн-система | Digital City, компоненты, адаптивность, Assets, токены |
| 03 \| Frontend | Главная, страницы, интерфейсы, интеграция с API |

| 06 \| GIS и маршрутизация | MapLibre, тайлы, геокодирование, маршруты |

Разделитель `|` в названиях чатов — часть имени; в таблице он экранирован. Это стартовая структура, а не предел: если направление содержит несколько самостоятельных задач, создавай дополнительные чаты с уникальными идентификаторами, например `04.1 | Backend — авторизация`. Не смешивай несвязанные задачи в одном чате. Новую задачу начинай в новом чате; исправления и проверки той же задачи веди в её исходном чате.

Порядок работы и передачи контекста:

- В начале проверь, поддерживает ли текущая среда создание чатов непосредственно в этом проекте. Если поддерживает, реально создай необходимые чаты через доступные инструменты, присвой им названия и передай задания. Не выдавай список названий за созданные чаты.
- Веди общую документацию в репозитории: `AGENTS.md` (единые правила), `docs/PROJECT-STATUS.md` (реестр задач, ответственные чаты, зависимости, статусы и блокеры), `docs/ARCHITECTURE.md` (архитектура и контракты) и `docs/HANDOFFS/` (результаты по задачам). Создай эти файлы, если их ещё нет; не перезаписывай существующие правила без проверки.
- Каждому рабочему чату передавай ID задачи, цель, границы ответственности, ссылки на актуальные документы и Assets, зависимости, критерии приёмки, разрешённые области изменений и ожидаемый результат. Не рассчитывай на автоматическую передачу истории между чатами.
- Работай с единым репозиторием и общими контрактами. При параллельной работе используй отдельные ветки или worktrees, не допускай одновременных конфликтующих изменений одних файлов; объединяй проверенные изменения через координатора. Не удаляй чужие изменения и не выполняй разрушительные команды без разрешения.
- Выполняй независимые задачи параллельно, если среда это поддерживает; зависимые — после готовности необходимых контрактов или результатов. Безопасность и тестирование учитывай с первого этапа, а не только в выделенных чатах в конце.
- Каждый рабочий чат по завершении фиксирует изменённые файлы, принятые решения, команды проверки, реальные результаты тестов, оставшиеся ограничения и следующего получателя. Координатор обновляет статусы, проверяет интеграцию и принимает результат только по критериям приёмки.
- Если среда не предоставляет инструментов для самостоятельного создания чатов внутри проекта, прямо сообщи об ограничении. Используй доступные отдельные агентские сессии, если они есть, обозначив, что это не чаты проекта. Если и они недоступны, подготовь готовые задания для отдельных чатов и попроси заказчика только о необходимом действии в интерфейсе. Не имитируй создание чатов и не утверждай, что работа идёт в фоне, если этого не происходит.

Главный принцип: один проект, единая архитектура, отдельный чат на каждую самостоятельную задачу, синхронизация через репозиторий и главный чат-координатор.

## 4. GIS, поиск, данные
MapLibre GL JS + разрешённые векторные тайлы OpenStreetMap (Martin/Planetiler или лицензированный провайдер); PostGIS, геокодирование Nominatim/Pelias на подходящей инфраструктуре; Valhalla для пеших, автомобильных и велосипедных маршрутов. Не используй публичные тайлы/геокодер как неограниченный production-бэкенд. Отображай атрибуцию и соблюдай ODbL. Настрой свой тёмный map style после изучения фактической схемы тайлов. Карта показывает реальные геоданные, а не SVG-превью. Геопоиск: geography(Point,4326), GiST, ST_DWithin, индексная сортировка; выдача должна иметь координаты и реальное расстояние. Для маршрутов — линия, манёвры, время и длина. Общественный транспорт и пробки — только с реальными источниками.

Импорт: адаптеры источников, очереди, нормализация, дедупликация, сопоставление филиалов, контроль происхождения, обновления, журнал ошибок, модерация. Первичный каталог: разрешённые данные OSM и открытые источники, заявки бизнеса. Яндекс Карты и 2ГИС подключать лишь по официальной лицензии, разрешающей конкретные операции хранения, импорта, отображения и коммерческого использования. Не обходить CAPTCHA, ограничения API и защиту сервисов; без лицензии адаптеры отключены. Полноту каталога не гарантировать. Хранить дату обновления, источник и лицензионный статус для каждого набора. Не переносить чужие фото и отзывы без прав.

## 9. Анимации и качество
Hero: мягкое появление заголовка, плавающие карты, лёгкий параллакс; маршрут — SVG stroke animation или реальная линия MapLibre; маркеры — пульсация; категории — stagger; отзывы — reveal; статистика — CountUp; sticky scroll-scrub для демонстрации; переходы, hover, skeleton. Не блокировать прокрутку; отключать ресурсоёмкие эффекты при prefers-reduced-motion и на слабых устройствах. Длительности 160–650 мс, никаких бесконечных тяжёлых WebGL-сцен в hero. Responsive 360/390/768/1024/1440/1920 px, клавиатура, focus-visible, WCAG 2.2 AA, достаточная контрастность, семантика. Цели LCP <= 2.5 s, INP <= 200 ms, CLS <= 0.1; подтвердить измерениями. Lazy load карты, изображения WebP, code splitting, кластеризация, виртуализация длинных списков. SEO: SSR, sitemap, robots, canonical, корректный LocalBusiness schema без выдуманных рейтингов.

## 10. Безопасность и правовые требования
Threat model, OWASP ASVS/Top 10; параметризованные SQL, валидация, XSS/CSRF/SSRF/BOLA/IDOR защита, RBAC, CSP, HSTS, строгий CORS, HttpOnly Secure SameSite cookies, Argon2id, MFA, rate limits и лимиты GIS-запросов, безопасная загрузка файлов, антивирус/проверка содержимого при необходимости, проверка webhook, защита от спама, мониторинг и WAF по необходимости. SAST, DAST, secret scanning, dependency audit, backup и проверка восстановления. Не хранить ключи во frontend. Соблюдать применимое законодательство РФ: персональные данные, локализация, реклама, платежи, согласия, минимизация и удаление данных. Перед запуском подготовить список вопросов для юриста и проверить актуальные требования. Никаких обещаний абсолютной невзламываемости.

Студия Patchvale: https://vk.ru/patchvale и https://t.me/patchvale.
Контакты редактируются в CMS. Не добавлять придуманные телефоны и почту.

## 12. Порядок работ и приёмка
Этап 1: архитектура, дизайн-система, главная, адаптивность, импорты разрешённых данных Смоленска, /map, геопоиск, маршрут, карточка, PWA. Этап 2: аккаунты, отзывы, CMS/админ, кабинет бизнеса, заявки. Этап 3: платежи, реклама, аналитика, масштабирование регионов. Каждый этап — рабочий инкремент. Проверить Playwright, unit/integration, API, авторизацию, лицензирование, WCAG, мобильные устройства, работу без геолокации, нулевую выдачу, отказ маршрутизатора, офлайн-заглушку, доступность API и восстановление. Приёмка: пользователь вводит существующий адрес Смоленска, выбирает кафе, видит реальные ближайшие места и строит маршрут внутри сервиса. Проверить точное написание адреса из исходного задания геокодером, не выдумывать координаты.

Результат: исходный код, README, .env.example, миграции, Docker, инструкции запуска и импорта, OpenAPI, PWA, документация дизайн-системы, реальные результаты тестов, отчёт безопасности, перечень открытых ограничений. Если отсутствуют ключи, лицензии, хостинг или платёжные данные, реализуй интерфейс интеграции и явно отметь блокер. Не скрывай незавершённые функции, не выдавай демо за production, не подменяй весь сайт изображением макета.
