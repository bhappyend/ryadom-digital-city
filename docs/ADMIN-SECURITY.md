## Findings and verification

### F13.1-01 [P1] Isolate catalog drafts from public place fields — packages/db/src/admin.ts:86 (initial snapshot)

An authenticated fresh-MFA Business Manager has `catalog:write` without `catalog:publish`. A valid PUT `/api/v1/admin/catalog/businesses/{existingImportedPlaceId}` with current version and a changed phone/website directly UPSERTs those values into `places`; the conflict clause preserves the existing `active=true`. Categories are also replaced immediately. Public `CatalogRepository.findPlaceBySlug/searchPlaces` reads those fields and considers an active imported record with `source_records` visible (`catalog.ts:9–23`). Expected: old public projection until separate authorized publish; actual source path changes public contacts/location without that permission. This is discrete publication authorization bypass, not merely UI status wording. Routed to00 for05.1. **OPEN pending independent fixed snapshot/PostGIS regression**; implementation still evolving. Required regression: public A → save draft B as write-only role → public remains A → denied publish leaves A → authorized publish atomically exposes B. No real catalog write performed by reviewer.

### F13.1-02 [P2] Reject ordinary Admin status changes to peers — packages/db/src/admin.ts:34 (initial snapshot)

`setUserStatus` allows an Admin with `users:suspend` to suspend another Admin: the only target hierarchy check rejects `super-admin` for non-super-admin actors. Self denial does not cover Admin A → Admin B. Expected per architecture: ordinary Admin cannot modify equal/higher privileged accounts. Actual path revokes B's sessions and increments security version. Routed to00/05.1; final line/hash and isolated regression pending, **OPEN**. Require no target row/version/session mutation on denied peer action, Super Admin → Admin allowed. A safe denied-attempt audit is permitted and expected; do not suppress it to satisfy this test.

### F13.1-03 [P2] Preserve media referenced by published content — packages/db/src/admin.ts:54 (intermediate snapshot)

A Content Manager with `media:write` can DELETE a ready image already referenced by a published CMS revision. `archiveMedia` unconditionally marks it archived; `getApprovedMedia` only serves ready records. Expected409 with published bytes still reachable; actual public image becomes unavailable without revising/publishing its document. Same issue applies to published place references. Routed to00/05.1; **OPEN pending fixed snapshot**. No active external image request or real asset mutation performed.

### F13.1-04 [P2] Persist the reason for each private phone disclosure — packages/db/src/admin.ts:123 (intermediate snapshot)

`revealOwnerPhone` requires a nonempty reason at DTO validation but ignores `b.reason`, then records only `['phone']` in a generic audit event. Migration003 has no dedicated reveal-reason row and audit_events has no reason column. Expected: recoverable reason tied to actor/owner/requestId/time/audit before returning sensitive phone; actual evidence cannot show why the disclosure was authorized. Routed to00/05.1; **OPEN pending fixed snapshot**. Store disclosure reason separately without plaintext phone and commit it with audit; audit failure must still prevent any phone response. A general PII-rich audit payload is not required.
