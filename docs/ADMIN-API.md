# Admin API — implemented slice 04.1

2026-11-27, Europe/Moscow. Local-only Next/Nest/PostGIS implementation; no deployment or production-readiness claim. Authoritative input/output schemas and 98 operation registrations: `packages/accounts-types/src`. This document distinguishes registered routes from implemented capabilities.

## Enable and configure

Default `ACCOUNTS_ENABLED` is false. Protected routes return401 without a configured account runtime; public account dependencies return503. To enable: apply DB migrations through003 and call DB `grant-admin-runtime` for the dedicated application service role, then provide `ACCOUNTS_ENABLED=true`, `ACCOUNTS_DATABASE_URL` (fallback APP_DATABASE_URL), REDIS_URL, ACCOUNT_MFA_KEY (canonical base64,32 random bytes), ACCOUNT_MFA_KEY_ID and ACCOUNT_RATE_KEY (canonical base64,32 random bytes). These are server-only, never NEXT_PUBLIC, args, responses or logs. Root17 manages ignored `.env.accounts.local` and runtime loading. The API does not run migrations or bootstrap automatically.

Production requires HTTPS approved CORS_ORIGINS. Cookies `__Host-ryadom-session` and `__Host-ryadom-preauth`: Secure/HttpOnly/SameSite=Lax/Path=/, no Domain. Explicit local HTTP is permitted only with NODE_ENV=development and ACCOUNT_ALLOW_LOOPBACK_HTTP=true, all configured origins exact loopback; dev cookie names differ. This does not weaken Origin/CSRF/MFA/RBAC checks. Production ignores this downgrade flag. Use HTTPS for release browser acceptance.

PUBLIC_MEDIA_ORIGIN is optional and must be an exact origin (no trailing slash/path/query/hash/credentials). HTTPS in production. HTTP only with NODE_ENV=development + PUBLIC_MEDIA_ALLOW_LOOPBACK_HTTP=true + exact loopback hostname. Missing configuration leaves public Place.photos empty, rather than inventing an origin. Detail and nearby projections join at most20 approved photos per place, at most50 places per page, preserve actual attribution/license/alt/sourceUrl and build absolute URLs from this explicit origin. Request Host/Origin/forwarded headers never select it. No remote fetch or proxy exists.

Local durable media defaults to ignored `.local-media/quarantine`, configurable via ACCOUNT_MEDIA_ROOT. Keep it outside frontend/public/static hosting and protect backup/access. Local adapter is implemented; S3, orphan cleanup, storage quotas and backup/restore remain operational follow-up. Never expose this directory as an unrestricted static mount.

## Browser authentication

1. POST `/api/v1/auth/csrf`, JSON `{}`, credentials included. Browser supplies Origin itself; do not manually set forbidden browser headers. Exact configured Origin is mandatory; missing/null/foreign and cross-site Fetch Metadata rejected. Only this registry handler is prior-CSRF exempt. GET of the same path remains strict-Origin compatibility transport.
2. POST `/auth/login` with email/password and `X-CSRF-Token`. Password is12–128 characters exactly as entered. Generic credential errors. Argon2id19456KiB/time2/parallelism1, no queue, max2 concurrent hashes; unknown accounts get dummy verification. Local benchmark29/30/28ms is not deployment tuning or load evidence.
3. Privileged account password yields `mfa_required` or `mfa_enrollment_required`, never an admin session. Refresh CSRF after every cookie rotation. Enrollment POST `/auth/mfa/enrollment` returns secret once for a locally constructed QR, followed by POST `/auth/mfa/enrollment/verify`. Ten recovery codes are returned once. No external QR service or email-verification fiction.
4. MFA verification consumes challenge and TOTP step/recovery code atomically with session issuance. RFC6238 SHA1/6digits/30s ±1step; consumed steps reject replay. Secrets AES256-GCM, keyId/nonce/tag, account-bound AAD; recovery codes salted scrypt hashes. Enrollment replacement requires a proven session/recovery context, not another stale password challenge.
5. GET `/auth/me`, POST `/auth/step-up`, POST `/auth/logout` are implemented. Step-up rotates session/CSRF and lasts5min. Ordinary initial MFA enrollment can follow password step-up; that password assurance never becomes admin/MFA assurance. Recovery sessions cannot access admin or step up, only re-enroll. Admin session idle15min/absolute8h; ordinary24h/7d. Current roles/status/security version are reloaded. Logout revokes durable state. Normal24h token rotation retains original absolute expiry.

POST `/auth/register` uses current published terms/privacy document versions, explicit consent and transactionally consumes preauth; no provider means email remains unverified. `/auth/policy` reports actual published versions and email/reset unavailable; no legal draft fallback. These endpoints are registered/implemented but require existing published legal CMS content. Admin bootstrap avoids a circular dependency by explicit independently accepted document versions, not fabricated publication.

All unsafe operations retain exact Origin+JSON+Fetch Metadata+context-bound constant-time CSRF checks. Nest registers exact operation handlers, so matched case/trailing-slash variants retain controls; encoded/double-slash alternatives do not gain a wildcard bypass. Inputs and envelopes use strict schemas; unknown fields and repeated/non-scalar query parameters rejected. JSON16KiB, URL4KiB remain. All API/private/media responses no-store.

Shared Redis ingress120/min/IP runs before any account lookup or denial-audit write; exceeded/outage admission writes no further audit rows. Per-operation budgets remain stricter: auth20/15min plus login5/email and20/IP per15min, register3/hour/IP, MFA10/15min/account and5 challenge attempts, writes20/min/account, phone reveal10/hour/operator, media tickets20/hour/operator. Account/private operations fail closed on Redis outage. HMAC identifiers, not raw IP/email, form Redis keys. Ingress budget is per trusted Express client IP; configure trusted reverse proxies narrowly. Reads of public stage1 catalog preserve their separate existing limiter behavior.

## Initial administrator

CLI only: build API, then run `node apps/api/dist/bootstrap-admin.js` in the user's interactive terminal. It rejects arguments and non-TTY use. No public bootstrap route, default password, auto-login or preconfigured production account exists.

Provide ACCOUNTS_BOOTSTRAP_DATABASE_URL (operator-only credential), ACCOUNT_BOOTSTRAP_SECRET_SHA256 and ACCOUNT_BOOTSTRAP_EXPIRES_AT (future instant at most15min away) through protected runtime configuration. The operator enters the actual one-time secret and password with hidden input, supplies identity-check basis and personally accepted legal versions, and explicitly confirms identity/consent. Exclusive DB transaction refuses a second super-admin bootstrap; audit records actor/action/time/request and changed fields. CLI never issues a session; real login and MFA enrollment remain mandatory. Remove bootstrap configuration after use. Independent identity verification itself is an operator responsibility; the CLI does not verify an external identity source or email provider. Do not ask an automated browser agent to choose or expose the user's credentials.

## Ownership and manual activation — final backend continuation

The existing100-operation registry now has real handlers for POST/GET `/business/claims`, POST `/business/claims/{claimId}/withdraw`, GET `/admin/claims`, POST `/admin/claims/{claimId}/decision`, and POST `/admin/listings/{listingId}/decision`. Migration004 and refreshed admin runtime grants are required before enabling accounts. Ordinary users can submit text evidence with consent, read only their own claim summaries, and withdraw only their pending claims. Evidence and verification notes are private administrative fields. Independent authorized staff with fresh MFA can verify/reject/revoke using an independent registry, a pre-existing verified contact, or an in-person check. Applicant assertions alone are insufficient. Staff cannot decide their own claim.

Claim decisions serialize per place and use expectedVersion. Verification atomically creates/reuses the business and branch and records an active membership, the decision ledger and audit. Concurrent competing verifications have one winner. A failed audit rolls back the membership and decision. Claim revocation removes applicable membership and demotes the corresponding published paid listing to pending-review. It preserves starter catalog data and original source records. Verification does not change account role, email verification, identity or MFA.

Admin listing approval requires an active actual applicant, independently verified claim with live membership, current accepted founder agreement tied to that applicant's nonarchived CRM record, matching confirmed RUB receipt whose funded period contains the database time, and an active licensed published place in an enabled city. Payment alone never publishes. Approval is CAS, audited, and denies the applicant as reviewer. Missing/expired funding, revoked claim, suspended applicant or stale version denies publication. Unverified active applicants can be published by an authorized independent administrator without fabricating email identity; sensitive owner-self routes still require actual verified identity and MFA.

First-install legal publication is an operator task, not a generated default: the authorized operator must use the admin CMS to save and explicitly publish reviewed `terms` and `privacy` legal documents with actual version identifiers and text. GET `/auth/policy` returns only those published versions; ordinary registration records explicit consent to those exact versions and rejects stale versions. Drafts or placeholder legal text must not be used as deployable policy. No policies, users, claims, receipts or paid periods are seeded by this continuation.

## Media transport

POST `/admin/media` creates a five-minute owner-bound ticket with declared real MIME, SHA256, byte length, rights, attribution and license. PUT `/admin/media/{uuid}/content` accepts raw application/octet-stream or the exact ticket raster MIME; no JSON/base64/multipart/URL fetch. Only this upload route is exempt from the16KiB JSON parser budget; authentication, Origin/CSRF, permission and step-up run before reading/decode. Max2MiB,4096 dimension,16M pixels, one frame, max2 simultaneous decodes. Exact JPEG/PNG/WebP container, declared MIME, byte length/hash and decoded format checked; appended payload rejected. Sharp rotates/re-encodes WebP without metadata. Atomic private file write followed by transactional ready state. A failed commit may leave an unreachable private orphan, never a public success.

GET `/media/{uuid}.webp` (no API prefix) serves only ready media currently referenced by published CMS or an active published catalog snapshot in an enabled city. WebP MIME/nosniff/no-store. Draft, expired ticket, archived/unreferenced/unknown/traversal paths are unavailable. Supplied trusted SVG brand assets remain immutable static selections; arbitrary SVG/HTML upload is rejected.
