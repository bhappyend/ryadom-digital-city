## Подключение во frontend

`@ryadom/ui` отдаёт исходный TypeScript/TSX; отдельной сборки и копии React нет. React 19 — peer dependency. В `apps/web` объявить workspace-зависимость `"@ryadom/ui": "0.1.0"` (делает владелец frontend/архитектуры) и при необходимости `transpilePackages: ['@ryadom/ui']` в Next config. Корневые package/lock/config задача 02 не изменяет, установку зависимостей выполняет архитектура. После появления `docs/ARCHITECTURE.md` прочитан контракт v1.0 и исходники `packages/types`: UI не зависит от DTO runtime, 14 идентификаторов совпадают. Dev-зависимости UI выровнены на точные @types/react 19.3.3 / react-dom 19.3.1; TypeScript предоставляет корень (6.0.3). Архитектуре нужно обновить lock после финального UI manifest.

В корневом layout Next:

```tsx
import '@ryadom/ui/fonts.css';
import '@ryadom/ui/styles.css';
import { Brand } from '@ryadom/ui';

// html lang="ru"; body className="dc-theme"
// styles.css уже импортирует неизменённый tokens.css.
// Для навигации: <Link href="/" aria-label="Рядом — на главную"><Brand /></Link>
```

`styles.css` включает ограниченную базу `.dc-theme`, отдельные классы `.dc-*` и `.dc-container`; не навязывает страницу или глобальный reset всем приложениям. `fonts.css` загружает только локальные `/assets/fonts/manrope/files/*.woff2`; нет запросов к Google Fonts, CDN и npm в браузере. Шрифты поставлены вместе с OFL-1.1 и provenance, установка npm для текущего подключения не нужна.

Проверенный альтернативный npm-путь: `@fontsource-variable/manrope@5.3.0`, `import '@fontsource-variable/manrope/wght.css'`, CSS family `Manrope Variable`. Официальная [инструкция Fontsource](https://fontsource.org/fonts/manrope/use) также поддерживает импорт пакета целиком; [лицензия](https://fontsource.org/fonts/manrope/about) — OFL-1.1. Не подключать оба способа одновременно. Если выбран npm-вариант, учесть имя family в `--font-ui` и inline-логотипе. Текущая локальная поставка использует CSS alias `Manrope`, чтобы исходный логотип и неизменённые токены работали вместе. Шесть unicode-подмножеств сохранены целиком, включая кириллицу и U+20BD (₽ в latin-ext). Оригинальный `wght.css` также сохранён для происхождения, он не импортируется приложением.

## Контракты компонентов

| Экспорт | Контракт и назначение |
|---|---|
| `Button` | Нативный `button`, по умолчанию `type="button"`; `variant`: primary/secondary/ghost/danger, `size`: sm/md/icon. `loading` выставляет busy и disabled, сохраняет текст. `ref` и остальные нативные props React 19 проходят в button. Для icon-only нужен `aria-label`. |
| `Brand` | Исходная геометрия и кириллица inline SVG; horizontal/mark, доступное имя «Рядом by Patchvale». Оригинал SVG использует живой текст, поэтому локальный Manrope обязателен. Сам компонент не является ссылкой. |
| `Icon` | `name` — union из 29 исходных контурных SVG. Статический JSX генерируется из оригиналов, `currentColor` наследуется. Без `label` декоративный, с `label` — role img. Не загружает XML в runtime. |
| `CategoryTile` | Кнопка с одним из 14 поставленных `tile-*.svg`, обязательным видимым `label`. `selected` задавать только для toggle-фильтра; без него `aria-pressed` отсутствует. Идентификаторы совпадают с `CATEGORY_IDS` из packages/types. «Все категории» — отдельная кнопка с Icon grid, отдельного tile в архиве нет. |
| `Badge` | Текстовый span, tone neutral/accent/warning/danger/info. Цвет дополняет явный текст; Badge не объявляет статус открытия и верификацию автоматически. |
| `Field` | Подписанный нативный input; `label`, `hint`, `error`, нативные props и ref. useId или переданный id связывает label/hint/error, aria-describedby объединяется с внешним, ошибка выставляет aria-invalid. Плейсхолдер не заменяет label. |
| `EmptyState` | Именованная section с h3, пояснением и optional action. Не делает запросы и не придумывает выдачу. Если уровень заголовка страницы другой — frontend должен согласовать иерархию. |
| `ProviderNotice` | Явное сообщение о недоступном провайдере, причина приходит из приложения. `announce` включает role status только для динамического изменения; статические notices не шумят в screen reader. |

`Button`, `Field`, notices имеют явную client boundary для интерактивности/hooks Next. Остальные компоненты работают без состояния. Не вкладывать ссылку в Button и не оборачивать Button ссылкой: навигация — `next/link` с классами `dc-button dc-button--secondary dc-button--md`; изменение состояния — Button. Не импортировать внутренний `icon-artwork` напрямую.

Пример формы и состояния:

```tsx
<Field id="address" name="address" label="Адрес в Смоленске"
  hint="Улица и номер дома" maxLength={200} autoComplete="street-address" />
<Button type="submit" loading={pending}>Найти поблизости</Button>
<ProviderNotice title="Маршрутизатор недоступен"
  description="Сейчас не удалось построить маршрут. Попробуйте ещё раз позже." />
```

Управление pending, AbortController, таймаутами, повтором запросов, focus после ошибки и живой областью количества результатов — ответственность frontend; библиотека не создаёт сеть, геолокацию, storage или фоновые процессы. Выбранный radius и category валидируются по API контрактам, а не по этим визуальным компонентам. React экранирует строки; нет dangerouslySetInnerHTML и внешних fetch/URL props для иконок. Не передавать непроверенные пользовательские HTML props/объекты стилей.

## Визуальный контракт

Точные CSS/JSON токены скопированы побайтово: фон `#061217`, поверхности `#0B1B22` / `#10242E`, текст `#F4F9FA`, muted `#A1B5BE`, primary `#25F5B0`, secondary `#9D9BFF`. Фиолетовый остаётся вспомогательным акцентом. Палитра, исходные иконки и бренд не заменены. Primary CTA мятный с тёмным текстом, secondary прозрачный с рамкой. Не добавлять стрелки в кнопки, градиенты, тяжёлый blur и glow к каждому контролу. В исходном hero уже есть маршрут, свечение и волна: повторять их слоями поверх картинки не нужно.

Контейнер `max-width: 90rem` (1440 px при базовом 16px), поля `clamp(1rem, 4vw, 4rem)`, сетка страницы 12 колонок. Отступы опираются на 4/8/12/16/24/32/48/64/96/120 px из JSON. Body минимум 1rem/16px, регулярно читаемые labels и badges минимум .875rem/14px. Заголовки 700–800, текст 400–500. Hero — `clamp(2.25rem, 5vw, 4.75rem)`, межстрочный 1.08–1.15, текстовый блок примерно 34–40ch. Не уменьшать текст ради попадания в скриншот. 12px в by Patchvale — неизменённая часть брендового lockup, не UI-label.

Референс 1536×1024 — коллаж лендинга и отдельных экранов карты/места. Не копировать его две половины как страницу и не использовать screenshot в hero. На лендинге визуальный вес hero примерно равный между текстом и сценой: живой заголовок/описание/CTA слева, город справа занимает около 55–65% визуальной площади; тёмный край исходной иллюстрации занимает приблизительно треть. Это наблюдаемые пропорции, не жёсткая разметка. На desktop текст помещается в 5–6 из 12 колонок, изображение может быть общим декоративным слоем с фиксированным aspect ratio. Не обрезать главный городской маркер и собор ради лишней карточки. Под hero быстрый поиск широкой строкой, далее компактные категории, пошаговое объяснение, демонстрация и данные согласно MASTER PROMPT.

Hero picture: `/assets/backgrounds/hero-city.webp` 1672×941; при ширине до 767px `/assets/backgrounds/hero-city-small.webp` 960×540. На мобильном текст идёт первым на сплошной тёмной поверхности, декоративный город ниже/позади без ухудшения читаемости. Размер картинки резервировать до загрузки; не lazy-load LCP hero, а карту и нижние секции грузить отдельно. Картинка декоративная: alt пустой. Фото реальных мест и аватары отсутствуют; использовать честные пустые состояния или вовсе скрывать неподтверждённые секции. Не заменять их сторонними изображениями.

## Responsive-приёмка frontend

Библиотека не создаёт страницу; перечисленные ниже viewport-проверки ещё должны быть выполнены после интеграции.

| Ширина | Ожидаемое поведение |
|---|---|
| 360 / 390 | Одна колонка hero, поля по 16px, поиск вертикально, категории по 2 колонки, длинные русские labels переносятся; CTA не обрезаются. Touch targets ≥44px; safe-area для bottom sheet/navigation. |
| 768 | Поиск перестраивается при реальном доступном месте; категории 3–4 колонки, без принудительного desktop header. Проверить планшет и увеличенный шрифт. |
| 1024 | Hero может стать двухколоночным, категории 4–7 по минимальной ширине. Карта/список перестраиваются по полезной области, не только ширине окна. |
| 1440 | Desktop 12 колонок, hero и строка поиска; текст/карта без горизонтальной прокрутки, достаточный отступ от sticky header. |
| 1920 | Контент ограничен 1440px; фон может растягиваться, типографика и карточки не растут бесконечно. |

Кроме стандартных ширин: zoom 200%, системный размер шрифта, длинные названия, ошибка в Field, busy/disabled button, reduced motion, forced colors, keyboard-only, сенсорный экран. Не делать фиксированную высоту текстовым карточкам. Page grid, меню, search combobox, диалоги и map bottom sheet должны отдельно пройти браузерную проверку frontend.

## Доступность и motion budget

Вычисленный WCAG contrast ratio для исходных токенов: text/background **17.87:1**, text/surface-raised **15.05:1**, muted/surface-raised **7.51:1**, on-primary/primary **13.34:1**, danger/surface **6.84:1**, warning/surface **11.49:1**, info/surface **7.79:1**. Это математическая проверка непрозрачных цветов, не полная WCAG-сертификация страницы. Decorative border/surface только **1.67:1**; для input и secondary button рамка взята из существующего muted (**8.26:1**), чтобы границы контрола различались. Токен border сохранён для декоративных панелей. Focus — 3px primary с offset 4px; проверить его видимость на фактическом фоне.

Минимальная высота кнопок 44–48px; смысл задаётся текстом, а не только цветом/иконкой. Категория объявляет toggle только при selected. Ошибку связывать с полем; при отправке переносить focus на первое ошибочное поле и сообщать итог кратко. Не использовать auto-focus и не запрашивать геолокацию при загрузке страницы. Map gesture handling не должен перехватывать внешнюю прокрутку; обязательны доступные поля, список результатов и zoom-кнопки вне canvas.

Библиотека: только hover color/border 160ms; loading spinner 650ms, только пока запрос ожидается. В reduced-motion transitions и spinner animation отключены. Frontend: разовые появления 160–650ms, без autoplay параллакса на touch/слабых устройствах; одновременно не более одного крупного декоративного эффекта. Sticky scrub — лишь демонстрация, без блокировки прокрутки, при reduced-motion последовательность статична. CountUp только подтверждённые API-показатели и только раз при появлении. Нет бесконечной WebGL-сцены в hero. LCP/INP/CLS ещё не измерены, целевые значения 2.5s/200ms/0.1 остаются критериями приложения.

## Anti-slop review

Не создан generic landing starter: библиотека использует точные исходные цвета, локальную кириллицу, поставленные категории и геометрию «Рядом». Карточки служат категориям и состояниям, не размножают рекламные обещания. Нет выдуманных рейтингов/статистики/отзывов, новых фотозамен, градиентов и декоративных стрелок CTA. Стек и исходные ассеты сохранены. Итоговую композицию, контраст поверх фото, responsive и визуальную верность должен проверить frontend на работающих страницах: библиотека сама по себе этого не доказывает.

## Проверки

Из корня: `python packages/ui/scripts/audit-assets.py` и `python packages/ui/scripts/generate-icons.py --check`. После установки архитектурой: `npm run typecheck --workspace=@ryadom/ui` и `npm test --workspace=@ryadom/ui`. SSR-тест работает в памяти через TypeScript и React DOM server, проверяет нативную семантику, aria-связи, local paths и экранирование; это не браузерная и не screen-reader-приёмка. Фактически выполненные команды и ограничения — в `docs/HANDOFFS/02.md`.
